## 1. 概述

### 1.1 中间层定位

本模块把 Android 系统级 `BluetoothHeadsetClient`（HFP Client，车机侧免提角色）封装成一套面向车机 HMI（人机接口）的稳定接口，解决四个问题：

1. **系统 API 不可直接引用**：`BluetoothHeadsetClient` 属于 `@SystemApi`，公开 SDK 无法编译，模块内部通过反射隔离。
2. **HFP 原始状态过于扁平**：HFP 只给出一组 `Call` 和状态码，没有“主叫/第二路/会议”的概念，模块负责归并成 UI 可直接消费的 `PhoneCallState`。
3. **三方通话分支复杂**：加拨、等待来电、接听并保持、接听并挂断、切换、合并会议，模块把这些动作和前置条件收敛为固定 API 与能力位。
4. **上层重复实现细节**：联系人回填、头像、计时、铃声、音频路由、麦克风静音、设备焦点、自动重连都在模块内完成。

车机无 SIM，因此模块**不使用** `TelephonyManager`、`Telecom`、`InCallService` 作为主链路；号码、电量、信号、运营商均来自 AG（手机）上报。

### 1.2 设计原则

| 原则 | 具体体现 |
|---|---|
| 单一事实源 | 所有 HFP 事件在名为 `BluetoothPhoneEngine` 的单线程上归并（实现类 `PhoneEngine`），UI 只读 `StateFlow` |
| 状态与事件分离 | 持续状态用 `StateFlow`；结束页、阶段变化等一次性信号用 `SharedFlow<PhoneEvent>` |
| 能力位驱动 UI | `canAnswer`、`canMerge`、`canAddCall` 等由模块计算，UI 不自行拼状态组合 |
| 网关可替换 | `HfpGateway` 隔离系统实现与模拟实现，同一套上层逻辑可跑真机与 Mock |
| 失败可解释 | 所有动作返回 `PhoneResult`，失败带 `PhoneError` 与可直接展示的 `message` |

### 1.3 能力矩阵

| 能力 | 支持 | 说明 |
|---|---|---|
| 已配对设备列表 / 配对 / 解绑 | 是 | 列表来自系统 `BluetoothAdapter`，本模块不主动扫描 |
| HFP 连接 / 断开 / 自动重连 | 是 | 退避重连，最多 3 次；主动断开不重连 |
| 单路来电、去电、接听、拒接、挂断 | 是 | 对应 ATA / ATD / CHUP |
| 保持、恢复、活动与保持互换 | 是 | `AT+CHLD=2` |
| 加拨第二路 | 是 | 活动或保持状态下均可 |
| 第二路来电（等待）三种策略 | 是 | 接听并保持 / 接听并挂断当前 / 只挂断第二路 |
| 会议合并 | 条件支持 | AOSP 14 未公开 CHLD=3，需厂商方法或厂商 AT 通道 |
| 每路独立通话时长 | 是 | 软件计时，保持期间继续累计 |
| 联系人姓名 / 头像 | 是 | 读取本机 `ContactsProvider`，号码后 10 位匹配 |
| 通话记录 | 是 | 读取系统 `CallLog` |
| DTMF | 是 | 单字符与整串，整串自动留 60ms 间隔 |
| 音频路由（车机 / 手机） | 是 | SCO/eSCO 连接与断开 |
| 麦克风静音 | 是 | 车机本地 `AudioManager`，非 HFP 标准能力 |
| 手机侧语音识别 | 是 | `startVoiceRecognition` / `stopVoiceRecognition` |
| 带内铃声适配 | 是 | `isInBandRing=true` 时静音本地铃声，避免双响 |
| 多设备 | 是 | 设备列表 + 单一“当前数据源” |
| VoIP / 微信识别 | 扩展点 | HFP 不带应用信息，需注入 `CallClassifier` |
| 会议参与者列表 | 否 | HFP 不提供，只有合并瞬间的第二路快照 |
| 黑名单、输入长度限制、键盘布局 | 否 | 属于 HMI 业务层 |

### 1.4 不在中间层范围内

- 拨号盘 UI、联系人选择页、通话记录页布局。
- 黑名单、骚扰拦截、号码归属地。
- 输入号码最大长度、按键布局与多语言文案。
- 通话录音、语音质量统计。
- SIM / 蜂窝网络管理（车机无 SIM）。

## 2. 接入准备

### 2.1 模块依赖

`settings.gradle.kts` 已包含模块：

```kotlin
include(":bluetoothphone")
```

应用模块引入：

```kotlin
dependencies {
    implementation(project(":bluetoothphone"))
}
```

模块以 `api` 方式导出协程库，因此应用侧无需重复声明即可使用 `StateFlow`、`viewModelScope` 等 API。

当前工程以源码模块方式接入；若后续拆分为独立仓库，可把 `:bluetoothphone` 发布为 AAR，公开包与 API 保持不变，应用侧只需替换依赖坐标。

### 2.2 权限

模块 `AndroidManifest.xml` 已声明以下权限，会随 Manifest 合并进入应用：

| 权限 | 类型 | 用途 |
|---|---|---|
| `BLUETOOTH_CONNECT` | 运行时 | Android 12+ 访问已配对设备、HFP 代理 |
| `BLUETOOTH_SCAN` | 运行时 | 扫描/发现周边设备（本模块仅声明，不主动扫描） |
| `BLUETOOTH_PRIVILEGED` | 系统签名 / priv-app | HFP Client 系统 API 的前提，普通应用无法获得 |
| `READ_CONTACTS` | 运行时 | 读取联系人与头像，用于通话界面 |
| `READ_CALL_LOG` | 运行时 | 读取通话记录 |
| `MODIFY_AUDIO_SETTINGS` | 普通 | 麦克风静音、音频路由 |

运行时建议申请 `BLUETOOTH_CONNECT`、`READ_CONTACTS`、`READ_CALL_LOG` 三项。`BLUETOOTH_SCAN` 在 Android 12+ 常被归入定位用途，拒绝后不应影响通话主链路。

```kotlin
private val permissionLauncher = registerForActivityResult(
    ActivityResultContracts.RequestMultiplePermissions()
) { granted ->
    // 无论是否全部授予都补一次刷新，中间层会按实际权限降级
    if (granted.isNotEmpty()) BluetoothPhone.get(this).refresh()
}

val required = arrayOf(
    Manifest.permission.BLUETOOTH_CONNECT,
    Manifest.permission.READ_CONTACTS,
    Manifest.permission.READ_CALL_LOG
)
val missing = required.filter {
    checkSelfPermission(it) != PackageManager.PERMISSION_GRANTED
}
if (missing.isNotEmpty()) permissionLauncher.launch(missing.toTypedArray())
```

### 2.3 系统集成要求（量产车机）

| 要求 | 说明 |
|---|---|
| 平台签名 | 使用车机平台证书签名，否则拿不到 `BLUETOOTH_PRIVILEGED` |
| 预置 priv-app | 安装到 `/system/priv-app` 或等效分区 |
| 蓝牙角色 | 车机作为 HFP Client（HF），手机作为 AG |
| 系统蓝牙服务 | 必须包含 `BluetoothHeadsetClient`，且在系统配置中启用 HFP Client profile（部分车机默认只启用 HFP AG） |
| 音频 HAL（硬件抽象层） | 通话音频走 SCO/eSCO；若使用独立音频通道，需要替换静音与路由实现 |

### 2.4 初始化

推荐在 `Application.onCreate` 显式初始化：

```kotlin
class CarPhoneApp : Application() {
    override fun onCreate() {
        super.onCreate()
        val canUseRealHfp = BluetoothPhone.isSystemApiAvailable() &&
            BluetoothPhone.hasPrivilegedPermission(this)
        BluetoothPhone.init(
            context = this,
            config = BluetoothPhoneConfig(
                useMockGateway = !canUseRealHfp,
                autoConnectLastDevice = true,
                autoReconnect = true
            )
        )
    }
}
```

`init` 会创建单例并立即启动链路；重复调用会先释放旧实例再创建新实例。

`get(context)` 用于未显式初始化时兜底：若系统没有 `BluetoothHeadsetClient` 或没有 `BLUETOOTH_PRIVILEGED`，会自动进入 Mock，避免崩溃。

> 量产应用不要依赖 `get` 的自动降级：权限异常时它会静默进入 Mock，界面看似正常但没有真实通话。应显式 `init(useMockGateway = false)`，并在启动时校验权限与 `isMock`。

> `init` 是“销毁旧实例 + 创建新实例”，不是幂等启动。不要在 Activity/Fragment 的 `onCreate` 中调用，否则每次页面重建都会断开链路、清空通话状态。只在 `Application.onCreate` 调用一次。

### 2.5 生命周期

| 方法 | 行为 |
|---|---|
| `init(context, config)` | 释放旧实例 → 创建 → 启动 |
| `get(context)` | 返回单例；不存在时按系统能力创建并启动 |
| `start()` | 启动/补偿启动；重复调用不会重建网关 |
| `stop()` | 停止监听、清空连接与通话状态；实例仍可再次 `start()` |
| `shutdown()` | 取消协程、关闭线程、释放实例；之后必须重新 `init/get` |
| `refresh()` | 重新拉取设备、通话、AG 与音频状态 |

`stop()` 与 `shutdown()` 都会补发 `CallEnded` / `SessionEnded`，UI 若在此期间仍订阅事件，会收到“通话结束”提示，这属于预期行为。

### 2.6 最小可用示例

```kotlin
// 1. 订阅状态
lifecycleScope.launch {
    BluetoothPhone.get(context).callState.collect { state ->
        render(state)
    }
}

// 2. 拨号
lifecycleScope.launch {
    when (val result = BluetoothPhone.get(context).dial("13800138000")) {
        is PhoneResult.Success -> Unit
        is PhoneResult.Failure -> showToast(result.message ?: result.error.name)
    }
}
```

## 3. 架构与线程模型

### 3.1 分层结构

```
┌─────────────────────────────────────────────┐
│ HMI（Activity / Fragment / ViewModel）       │
│ 只读 StateFlow，只调用 BluetoothPhone 方法    │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│ BluetoothPhone（进程单例 / 公共门面）         │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│ PhoneEngine（唯一事实源 / 单线程归并）         │
│  ├─ DeviceRegistry   设备列表与当前设备       │
│  ├─ CallStateStore   通话状态归并与能力位      │
│  ├─ ContactRepository 联系人 / 通话记录       │
│  ├─ RingtonePlayer   本地铃声                │
│  └─ PhonePreferences 上次连接设备             │
└──────────────────────┬──────────────────────┘
                       │ HfpEvent
┌──────────────────────▼──────────────────────┐
│ HfpGateway（internal 接口）                  │
│  ├─ SystemHfpGateway  反射调用系统 API        │
│  └─ FakeHfpGateway    模拟链路                │
└──────────────────────┬──────────────────────┘
                       │ 系统蓝牙广播 / 代理
┌──────────────────────▼──────────────────────┐
│ BluetoothHeadsetClient（@SystemApi）          │
└─────────────────────────────────────────────┘
```

PBAP 是独立旁路：`PbapGateway` 只负责触发系统同步电话本，实际数据仍从 `ContactsProvider` 读取。

### 3.2 线程规则

| 组件 | 线程 | 说明 |
|---|---|---|
| 网关事件 | 系统广播线程 / Binder 线程 | 通过 `MutableSharedFlow`（缓冲 64）投递，不阻塞广播 |
| `PhoneEngine` | 单线程执行器（线程名 `BluetoothPhoneEngine`） | 所有状态写入、事件归并、动作执行都在此线程 |
| 通话/设备类 `suspend` 方法 | 切换到引擎线程 | 内部 `withContext(dispatcher)`，调用方可在主线程直接调用 |
| 联系人 / 通话记录 | `Dispatchers.IO` | 查询数据库，不占用引擎线程 |
| UI | 主线程 | 收集 `StateFlow` 后直接渲染 |

结论：**应用侧不需要自己做线程切换**，在主线程 `lifecycleScope.launch { phone.dial(...) }` 即可。

### 3.3 数据流

```
系统广播（连接/音频/通话/AG）
        ↓
SystemHfpGateway 转成 HfpEvent
        ↓
PhoneEngine.onGatewayEvent 串行处理
        ↓
DeviceRegistry / CallStateStore 归并
        ↓
PhoneCallState（StateFlow）
        ↓
HMI 渲染 + PhoneEvent（一次性事件）
```

### 3.4 状态归并的关键约定

- 当已有活动通话、AG 却把第二路上报为 `INCOMING` 时，统一归一化为 `WAITING`，保证“接听并保持/接听并挂断”按钮可用。
- 会议既可能在 `ACTIVE`，也可能被保持为 `HELD`，两种情况都通过 `conference` 暴露。
- 合并会议时，原“活动 + 保持”两个 call 会被一个 `isMultiParty` call 替代；机制会保留第二路快照 `conferencePeer`，仅用于展示姓名/头像，其 `state` 不再代表实时状态。
- 联系人姓名与头像按号码后 10 位回填，兼容国家码差异；回填有 30 秒节流，避免启动阶段重复全表查询。
- 只有同一台手机前后两次快照对比才会判定“某一路结束”，切换设备不会误报。

### 3.5 多设备焦点策略

- `devices` 包含所有已配对设备，排序为：当前设备 → 已连接 → 名称。
- `activeDevice` 优先取用户选择，否则取第一台已连接设备。
- 新设备连接成功时，若当前已有可用设备，不抢占焦点。
- 某台设备上报通话时，仅当“当前没有通话”或“事件属于当前设备”才切换数据源，避免隐藏正在进行的通话。
- 设备断开时，优先跟随仍有通话的设备，其次才是任意已连接设备。
- `selectDevice(address)` 只切换 UI 数据源，不改变 HFP 连接。

### 3.6 重连与服务恢复

| 场景 | 行为 |
|---|---|
| 被动断线 | 按 `reconnectDelayMs × (attempt + 1)` 退避，最多 3 次 |
| 主动 `disconnect` | 加入手动断开集合，不自动重连 |
| `removeBond` | 清理本地状态，不重连 |
| 系统蓝牙服务重启 | 发 `PhoneEvent.Info`，500ms 后重建代理并刷新 |
| 蓝牙关闭 | 清空设备连接、通话、音频、静音与铃声 |
| 蓝牙重新打开 | 重新获取代理、同步电话本、自动连接上次设备 |

## 4. 数据模型

### 4.1 枚举

#### ProfileState

| 值 | 含义 |
|---|---|
| `DISCONNECTED` | 未连接 |
| `CONNECTING` | 连接中 |
| `CONNECTED` | 已连接 |
| `DISCONNECTING` | 断开中 |
| `UNKNOWN` | 未知 |

#### BondState

`NONE` 未配对、`BONDING` 配对中、`BONDED` 已配对、`UNKNOWN` 未知。

#### CallState

| 值 | 含义 | 对应 HFP |
|---|---|---|
| `INCOMING` | 普通来电振铃 | 4 |
| `WAITING` | 通话中第二路来电 | 5 |
| `DIALING` | 去电拨号中 | 2 |
| `ALERTING` | 对方振铃中 | 3 |
| `ACTIVE` | 通话中 | 0 |
| `HELD` | 已保持 | 1 |
| `HELD_BY_RESPONSE` | 对方主动保持 | 6 |
| `TERMINATED` | 已结束 | 7 |

`isIncoming` 包含 `INCOMING` 与 `WAITING`；`isHeld` 包含 `HELD` 与 `HELD_BY_RESPONSE`。

#### CallDirection / CallKind

| 枚举 | 值 | 说明 |
|---|---|---|
| `CallDirection` | `INCOMING` / `OUTGOING` / `UNKNOWN` | 方向；无号码时为 `UNKNOWN` |
| `CallKind` | `CELLULAR` / `VOIP` / `UNKNOWN` | 通话来源，默认 `UNKNOWN`，由 `CallClassifier` 补充 |

#### CallUiState

| 值 | 含义 |
|---|---|
| `IDLE` | 无通话 |
| `INCOMING` | 单路来电响铃 |
| `OUTGOING` | 去电拨号或对方振铃，尚未接通 |
| `ACTIVE` | 单路通话中 |
| `HELD` | 只有一路保持 |
| `WAITING` | 通话中收到第二路来电 |
| `MULTI_CALL` | 两路及以上普通通话 |
| `CONFERENCE` | 会议通话 |

#### AudioState / AudioRoute

`AudioState`：`DISCONNECTED` / `CONNECTING` / `CONNECTED` / `UNKNOWN`。
`AudioRoute`：`CAR`（车机）/ `PHONE`（手机）。

#### PhoneConnectionState

| 值 | 含义 |
|---|---|
| `BLUETOOTH_OFF` | 蓝牙未开启 |
| `NO_DEVICE` | 蓝牙已开但没有已连接手机 |
| `CONNECTING` | 有设备正在连接且尚无已连接设备 |
| `CONNECTED` | 至少一台手机已连接 |

### 4.2 PhoneDevice

| 字段 | 类型 | 说明 |
|---|---|---|
| `address` | `String` | MAC 地址，设备唯一标识 |
| `name` | `String?` | 蓝牙名称 |
| `alias` | `String?` | 系统别名，优先于 `name` |
| `bondState` | `BondState` | 配对状态 |
| `hfpState` | `ProfileState` | HFP 连接状态 |
| `isActive` | `Boolean` | 是否为当前数据源 |
| `battery` | `Int?` | 手机电量百分比 |
| `signal` | `Int?` | HFP 信号等级（通常 0–5，不是 dBm） |
| `roaming` | `Boolean?` | 是否漫游 |
| `operatorName` | `String?` | 运营商名称 |
| `audioState` | `AudioState` | 该设备的 SCO 状态 |

派生属性：

- `displayName`：`alias` > `name` > `address`。
- `isConnected`：`hfpState == CONNECTED`。

### 4.3 CallInfo

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | HFP call 标识，仅在同一次连接内稳定 |
| `deviceId` | `String` | 所属手机地址 |
| `state` | `CallState` | 当前状态 |
| `direction` | `CallDirection` | 方向 |
| `number` | `String?` | 号码；会议可能为空 |
| `displayName` | `String?` | 联系人姓名；未匹配时等于号码 |
| `photoUri` | `String?` | 联系人头像 URI；无权限/未匹配为 null |
| `isMultiParty` | `Boolean` | 是否会议通话 |
| `isInBandRing` | `Boolean` | 是否带内铃声 |
| `kind` | `CallKind` | 通话来源 |
| `startedAtMillis` | `Long?` | 接通时刻（墙上时间）；未接通为 null |

派生属性与方法：

| 成员 | 说明 |
|---|---|
| `isActive` | `state == ACTIVE` |
| `isIncoming` | 来电或等待 |
| `isHeld` | 任一保持状态 |
| `isVoip` | `kind == VOIP` |
| `isTimed` | 已接通（`ACTIVE` 或保持）且 `startedAtMillis != null` |
| `title()` | 会议无号码返回“会议通话”；否则姓名 > 号码 > “未知号码” |
| `durationSeconds(now)` | 已通话秒数，未接通返回 0 |
| `durationText(now)` | `mm:ss`，超过一小时 `h:mm:ss`；未接通返回空串 |

### 4.4 通话时长口径

- **起算点（正常流转）**：首次观测到该路进入 `ACTIVE` 或保持状态；若服务启动时通话已存在，则用 call 创建时间近似。
- **不计入**：来电振铃、去电 `DIALING` / `ALERTING`。
- **保持仍计时**：保持不释放话路，运营商按“接通到挂断”计费，手机原生 UI 也持续计时。
- **会议**：合并后的会议继承第一路的接通时刻；`conferencePeer` 保留第二路自己的接通时刻，两者独立累计。
- **HFP 不传输接通时间**：若服务在通话已建立后才启动，只能拿 call 创建时间近似，可能比手机侧短几秒。
- 对外提供 `formatDuration(seconds)`，避免各 HMI 各写一套格式化。

| 能力位 | 为 true 的条件 | 对应动作 |
|---|---|---|

| `canReject` | 有来电或等待 | `reject()` |
| `canHangup` | 有活动通话 | `hangup()` |

| `canHold` | 有活动通话且无等待 | `hold()` |
| `canSwap` | 同时有活动和保持，且无等待 | `swap()` |
| `canResume` | 无活动、有保持、无等待/去电 | `hold()` |

### 4.8 三方通话状态矩阵

| 场景 | active | held | incoming | waiting | outgoing | conference | uiState |
|---|---|---|---|---|---|---|---|
| 无通话 | – | – | – | – | – | – | `IDLE` |
| 单路来电 | – | – | ✓ | – | – | – | `INCOMING` |
| 去电（拨号/对方振铃） | – | – | – | – | ✓ | – | `OUTGOING` |
| 单路通话 | ✓ | – | – | – | – | – | `ACTIVE` |
| 单路保持 | – | ✓ | – | – | – | – | `HELD` |
| 通话中第二路来电 | ✓ | – | – | ✓ | – | – | `WAITING` |
| 会议中第二路来电 | ✓(multiParty) | – | – | ✓ | – | ✓ | `WAITING` |
| 接听第二路并保持第一路 | ✓ | ✓ | – | – | – | – | `MULTI_CALL` |
| 保持中加拨第二路 | – | ✓ | – | – | ✓ | – | `MULTI_CALL` |
| 会议进行中 | ✓ | – | – | – | – | ✓ | `CONFERENCE` |
| 会议被保持 | – | ✓ | – | – | – | ✓ | `CONFERENCE` |
| 普通通话 + 保持的会议 | ✓ | ✓ | – | – | – | ✓ | `MULTI_CALL` |
| 通话中 + 第二路去电 | ✓ | – | – | – | ✓ | – | `MULTI_CALL` |

两个容易误判的点：

1. **保持中加拨**时 `uiState` 是 `MULTI_CALL` 而不是 `OUTGOING`，因为已经有一路保持。界面应同时读 `outgoing` 展示“第二路去电中”。
2. **等待来电优先级最高**：会议中收到第二路时 `uiState` 为 `WAITING`，但 `conference` 仍然非空，恢复会议展示时不要只看 `uiState`。

## 5. 事件系统

### 5.1 PhoneEvent 类型

| 事件 | 触发时机 | 典型用途 |
|---|---|---|
| `Info(message)` | 服务重连等普通提示 | Toast / Snackbar |
| `Error(message)` | 权限缺失、反射调用失败、网关错误 | 错误提示 / 日志 |
| `CallUiChanged(previous, current)` | 界面阶段变化 | 埋点、一次性转场动画 |
| `CallEnded(call)` | 某一路结束（合并会议时不会误报参与方） | 日志、局部动画 |
| `SessionEnded(lastCall)` | 当前手机全部通话结束 | 结束页、结束提示 |
| `SessionEnded(null)` | 无通话信息时结束 | 兜底提示 |

### 5.2 消费方式

```kotlin
viewModelScope.launch {
    phone.events.collect { event ->
        when (event) {
            is PhoneEvent.Info -> showMessage(event.message)
            is PhoneEvent.Error -> showMessage(event.message)
            is PhoneEvent.CallUiChanged -> analytics.track(event.previous, event.current)
            is PhoneEvent.CallEnded -> log("call ended: ${event.call.title()}")
            is PhoneEvent.SessionEnded -> showEndPage(event.lastCall)
        }
    }
}
```

### 5.3 注意事项

- `events` 是 `replay = 0` 的 `SharedFlow`，**订阅之前发生的事件不会补发**。页面重建时应以 `callState` 为准，事件只做提示。
- 不要用 `CallEnded` 判断“全部结束”，它只代表某一路；结束页统一用 `SessionEnded`。
- `stop()`、蓝牙关闭、设备断开、解绑都会主动补发结束事件，便于界面复位。
- 事件缓冲为 16，极端高频场景可能丢弃；关键状态必须以 `StateFlow` 为准。

### 6.3 通话控制

| 方法 | 作用 | 前置条件 | HFP 动作 |
|---|---|---|---|
| `dial(number)` | 新拨一路 | 当前无任何通话、无等待 | `ATD` |
| `addCall(number)` | 加拨第二路 | `canAddCall` | `ATD`，AG 自动保持原通话 |
| `answer()` | 接听响铃中的一路 | `canAnswer` | `ATA` |
| `reject()` | 拒接来电或等待 | `canReject` | `AT+CHUP` |
| `hangup()` | 挂断活动通话 | 有 `active` | `terminateCall` |
| `hangupHeld()` | 挂断保持通话 | 有 `held` | `terminateCall` |
| `hangupWaiting()` | 只挂断第二路等待 | 有 `waiting` | `rejectCall`（`AT+CHUP`） |
| `hold()` | 保持/恢复/切换 | 有活动或保持，且无等待 | `AT+CHLD=2` |
| `swap()` | 活动与保持互换 | 同时有活动与保持，且无等待 | `AT+CHLD=2` |
| `merge()` | 合并为会议 | `canMerge` | 厂商方法或 `+CHLD=3` |
| `answerWaiting(holdCurrent)` | 接听等待来电 | 有 `waiting` | 保持=`CHLD=2`；挂断=`CHLD=1` |
| `answerWaitingAndHold()` | 接听并保持当前 | 同上 | `CHLD=2` |
| `answerWaitingAndEndActive()` | 接听并挂断当前 | 同上 | `CHLD=1` |

补充说明：

- `answerWaiting` 在**没有活动通话**时会退化为普通接听，不会发送无意义的保持/挂断标志。
- `merge()` 需要系统提供合并通道（`conferenceMergeSupported`），且手机协议栈接受 `CHLD=3`；最终以返回值与后续状态为准。
- `hangupWaiting()` 走 `AT+CHUP`。多数 AG 会作用于等待中的那一路，但不同 AG 行为存在差异，量产需要实测；若发现误挂当前通话，应改用厂商 AT 通道发送 `CHLD=0`。
- 会议本体可能在 `active` 或 `held`，挂断时按当前字段选择 `hangup()` 或 `hangupHeld()`。
- `swap()` 在只有保持通话时会退化为恢复；UI 以 `canSwap` / `canResume` 为准。
- 当前版本没有独立的“取消去电”接口：`hangup()` 只作用于 `active`，去电中的一路需要等对方接听/挂断或由手机侧结束。若产品要求取消去电，需要在模块内补充对 `outgoing` 的 `terminateCall` 封装。

#### 接听目标选择

| 场景 | 使用接口 |
|---|---|
| 普通来电 | `answer()` |
| 等待来电，但没有活动通话 | `answer()` 或 `answerWaiting(true)` |
| 等待来电 + 当前通话，保持当前 | `answerWaitingAndHold()` |
| 等待来电 + 当前通话，挂断当前 | `answerWaitingAndEndActive()` |

#### 挂断目标选择

| 想结束的对象 | 使用接口 |
|---|---|
| 活动通话 / 活动会议 | `hangup()` |
| 保持通话 / 保持会议 | `hangupHeld()` |
| 第二路等待来电 | `hangupWaiting()`（或 `reject()`） |
| 普通来电（未接听） | `reject()` |

### 6.4 DTMF 与语音识别

| 方法 | 说明 |
|---|---|
| `sendDtmf(code: Char)` | 单字符，仅允许 `0-9`、`*`、`#` |
| `sendDtmf(dtmf: String)` | 整串，逐字符发送，间隔 60ms；用于分机号、卡号 |
| `voiceRecognition(start)` | 启动/停止手机侧语音识别（`AT+BVRA`） |

DTMF 只对 `ACTIVE` 通话有效，保持中的一路不能发送。

### 6.5 音频与静音

| 方法 | 说明 |
|---|---|
| `setAudioToCar()` | 建立 SCO/eSCO；已连接或连接中直接成功 |
| `setAudioToPhone()` | 断开 SCO，把声音交回手机；已断开直接成功 |
| `toggleAudioRoute()` | 按当前路由切换 |
| `setAudioRoute(route)` | 枚举版本 |
| `setMicMute(muted)` | 车机本地麦克风静音 |
| `toggleMicMute()` | 切换静音 |

边界：

- 所有音频/静音动作都要求 `hasVoiceSession`；只有来电振铃时调用会返回 `NO_CALL`。
- 音频切换操作的目标设备优先跟随当前通话所属手机。
- 麦克风静音走 `AudioManager.setMicrophoneMute`，不是 HFP 标准能力；系统拒绝时返回 `NOT_SUPPORTED`。
- 通话结束、蓝牙关闭、`stop()`、`shutdown()` 时会自动恢复静音，避免下一通电话没声音。

### 6.6 通讯录与通话记录

| 方法 | 说明 | 权限 |
|---|---|---|
| `loadContacts(limit = 500)` | 读取联系人，按号码去重 | `READ_CONTACTS` |
| `loadCallLog(limit = 200)` | 读取通话记录，按时间倒序 | `READ_CALL_LOG` |

`Contact`：`id`、`name`、`number`、`photoUri`、`type`。

## 7. UI 集成指南

### 7.1 分域订阅

一个 `PhoneCallState` 同时包含通话、音频、会议、计时信息，整页 `render(state)` 会把无关区域一起重算。推荐按状态域拆分订阅。下面的 `uiState` 是页面级状态（字段可按需裁剪，参见 7.8 的最小模板）：

```kotlin
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        // 通话域
        launch {
            vm.uiState.map { it.call }.distinctUntilChanged().collect(::renderCall)
        }
        // 设备域
        launch {
            vm.uiState.map { it.devices }.distinctUntilChanged().collect(::renderDevices)
        }
        // 连接域
        launch {
            vm.uiState.map { it.connection to it.activeDevice }
                .distinctUntilChanged()
                .collect { (c, d) -> renderConnection(c, d) }
        }
        // 输入域
        launch {
            vm.uiState.map { it.number }.distinctUntilChanged().collect(::renderNumber)
        }
        // 提示域
        launch {
            vm.uiState.map { it.status }.distinctUntilChanged().collect(::renderStatus)
        }
        // 计时域
        launch {
            vm.uiState.map { it.call.hasTimedCall }.distinctUntilChanged()
                .collectLatest { timed ->
                    while (timed) {
                        renderDurations(vm.uiState.value.call)
                        delay(1_000.milliseconds)
                    }
                }
        }
    }
}
```

这样做的好处：

- 拨号输入变化只刷新输入框，不会重建通话列表。
- 设备列表按快照比较，内容未变时跳过 `inflate`。
- 计时器每秒只改时长文本，不写回 `uiState`，避免触发整页重组。

### 7.2 幂等写入

`TextView.setText` 相同文本也会走一次布局检查，建议封装：

```kotlin
private fun TextView.renderText(value: CharSequence) {
    if (text.toString() != value.toString()) text = value
}
```

列表类区域先比较快照再重建；重建时按 `CallInfo.id` 缓存行 View，供计时器只更新对应行。

### 7.3 状态到界面的推荐映射

| uiState | 主界面 | 操作区 |
|---|---|---|
| `IDLE` | 无通话空态 | 拨号盘 |
| `INCOMING` | 来电人姓名/号码/头像 | 接听、拒接 |
| `OUTGOING` | 去电人 + “正在呼叫” | 等待接通（当前无取消接口） |
| `ACTIVE` | 通话人 + 计时 | 保持、挂断、DTMF、音频、静音 |
| `HELD` | 保持中 + 计时 | 恢复、挂断保持、加拨 |
| `WAITING` | 当前通话 + 第二路来电浮层 | 接听并保持、接听并挂断、只挂断、拒接 |
| `MULTI_CALL` | 两路卡片（主/次） | 切换、合并、分别挂断 |
| `CONFERENCE` | 会议卡片 + 会议对方 | 挂断会议、DTMF、音频、静音 |

### 7.4 姓名与头像

- 主叫：`call.primaryCall?.displayName`、`photoUri`。
- 第二路：`call.secondaryCall?.displayName`、`photoUri`。
- 会议对方：`call.conferencePeer?.displayName`、`photoUri`。
- 会议本体：`call.conference?.title()`。

`photoUri` 是 `ContactsProvider` 的 content URI，加载示例：

```kotlin
suspend fun ImageView.loadPhoto(uri: String?) = withContext(Dispatchers.IO) {
    val resolver = context.contentResolver
    val bitmap = uri?.takeIf { it.isNotBlank() }?.let { text ->
        runCatching {
            resolver.openInputStream(Uri.parse(text))?.use(BitmapFactory::decodeStream)
        }.getOrNull()
    }
    withContext(Dispatchers.Main) {
        if (bitmap != null) setImageBitmap(bitmap) else setImageResource(R.drawable.ic_avatar_placeholder)
    }
}
```

量产建议使用 Coil/Glide 并配置占位图与圆角；模块只提供 URI，不负责图片解码。

### 7.5 时长显示

```kotlin
// 每一路独立计时
item.tvDuration.isVisible = item.isTimed
item.tvDuration.text = item.durationText()

// 会议对方（合并前第二路）
call.conferencePeer?.takeIf { it.isTimed }?.let {
    tvPeerDuration.isVisible = true
    tvPeerDuration.text = "会议对方时长 ${it.durationText()}"
}
```

### 7.8 最小 ViewModel 模板

```kotlin
data class CallUi(
    val call: PhoneCallState = PhoneCallState(),
    val connection: PhoneConnectionState = PhoneConnectionState.NO_DEVICE,
    val devices: List<PhoneDevice> = emptyList(),
    val activeDevice: PhoneDevice? = null,
    val isMock: Boolean = false,
    val message: String? = null
)

class CallViewModel(app: Application) : AndroidViewModel(app) {
    private val phone = BluetoothPhone.get(app)
    private val _ui = MutableStateFlow(CallUi(isMock = phone.isMock))
    val ui: StateFlow<CallUi> = _ui.asStateFlow()

    init {
        viewModelScope.launch {
            combine(
                phone.callState,
                phone.connectionState,
                phone.devices,
                phone.activeDevice
            ) { call, connection, devices, active ->
                _ui.value.copy(
                    call = call,
                    connection = connection,
                    devices = devices,
                    activeDevice = active
                )
            }.collect { _ui.value = it }
        }
        viewModelScope.launch {
            phone.events.collect { event ->
                when (event) {
                    is PhoneEvent.Error -> show(event.message)
                    is PhoneEvent.SessionEnded -> show("通话已结束")
                    else -> Unit
                }
            }
        }
    }

    fun answer() = action { phone.answer() }
    fun hangup() = action { phone.hangup() }

    private fun action(block: suspend () -> PhoneResult<Unit>) {
        viewModelScope.launch {
            when (val result = block()) {
                is PhoneResult.Success -> Unit
                is PhoneResult.Failure -> show(result.message ?: result.error.name)
            }
        }
    }

    private fun show(message: String) {
        _ui.value = _ui.value.copy(message = message)
    }
}
```

Activity/Fragment 只做两件事：`vm.ui.map { it.call }.distinctUntilChanged().collect(::renderCall)`，以及把按钮点击转发给 `vm`。

`PhoneCallState` 是不可变快照，`MutableStateFlow` 会按 `equals` 去重，相同状态不会重复发射；但 `calls` 列表变化仍会让整个 `callState` 发射，因此仍需按域订阅。

## 9. 配置项

`BluetoothPhoneConfig` 为 `data class`，支持 `@JvmOverloads`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `useMockGateway` | `false` | `true` 使用模拟 HFP，仅用于普通手机/模拟器 |
| `autoConnectLastDevice` | `true` | 启动后自动连接上次成功连接的设备 |
| `autoReconnect` | `true` | 被动断线后自动重连 |
| `reconnectDelayMs` | `3000` | 重连基础间隔，按尝试次数递增 |
| `conferenceVendorId` | `0` | 厂商 AT 通道 ID |
| `conferenceAtCommand` | `"+CHLD=3"` | 厂商通道发送的会议合并命令 |
| `logTag` | `"BluetoothPhone"` | 日志 TAG，配合 `adb logcat -s` 过滤 |
| `logLevel` | `PhoneLogLevel.INFO` | 日志级别；量产可设 `WARN` 或 `NONE` |
| `callClassifier` | `null` | 号码来源分类器 |

自动重连实际间隔为 `reconnectDelayMs × (attempt + 1)`，最多 3 次，即默认 3s、6s、9s。

## 11. 兼容性与已知边界

### 11.1 系统 API 与反射

- `BluetoothHeadsetClient` 是 `@SystemApi`，模块用反射隔离；系统版本升级可能改变方法签名。
- HFP 音频状态在 Client 广播中是 `10/11/12`，模块同时兼容旧版/厂商栈的 `0/1/2`。
- `removeBond` 是隐藏 API，同样通过反射调用。
- 反射方法缓存只缓存命中的方法，避免 `ConcurrentHashMap` 存 null 触发 NPE。

### 11.2 会议合并

- AOSP Android 14 的 `BluetoothHeadsetClient` 没有公开 `CHLD=3`。
- 模块先尝试厂商方法 `conferenceCall` / `mergeCall` / `mergeCalls`，再尝试 `sendVendorAtCommand(vendorId, "+CHLD=3")`。
- `conferenceMergeSupported` 只表示“存在合并通道”，**不代表手机一定接受**；最终以 `merge()` 返回值与 `conference` 是否出现为准。
- HFP 不提供会议参与者列表，`conferencePeer` 只是合并瞬间的第二路快照；若服务启动时会议已存在，该字段可能为空。

### 11.3 AG 差异

- 部分 AG 把第二路来电上报为 `INCOMING` 而非 `WAITING`，模块在有活动通话时统一归一化为 `WAITING`。
- 部分 AG 在存在等待来电时，`CHLD=2` 会接听等待而不是保持；因此 `canHold` / `canSwap` / `canMerge` 在 `waiting != null` 时全部为 false。
- `AT+CHUP` 对等待来电的处理存在 AG 差异，`hangupWaiting()` 需要量产实测。
- 去电方向只能依赖 AG 的 `isOutgoing` 标记；无标记时模块按来电处理。

### 11.4 音频与静音

- 麦克风静音是车机本地 `AudioManager` 能力，不影响手机侧麦克风；若量产使用独立音频 HAL，需要替换 `PhoneEngine.changeMicMute`。
- `micMuted` 只反映中间层自己设置的静音状态，不监听系统或其他应用的静音变更；若多应用共享麦克风，需要在集成层统一管理。
- `audioRoute` 依据 SCO 状态推导：`CONNECTED` / `CONNECTING` 视为车机，其余视为手机；无通话时为 null。
- 带内铃声 `isInBandRing=true` 时本地铃声会被静音，避免与手机侧铃声双响；等待来电只响一轮。

### 11.5 计时

- HFP 不传输接通时间，正常流转时模块从首次观测到 `ACTIVE`/保持开始计时。
- 服务在通话建立后才启动时，用 call 创建时间近似，可能比手机通话记录短几秒。
- 保持期间继续计时，与手机原生 UI、运营商计费口径一致。
- 若要统计“有效通话时长”，应新增字段，不要修改现有 `durationSeconds` 语义。

### 11.6 其他

- 联系人匹配使用号码后 10 位，国际号码格式差异可能导致匹配失败。
- 单次自动回填最多读取 2000 条联系人，30 秒内不重复读取。
- 多设备场景只有一个数据源；两台手机同时通话时，界面只展示当前设备，另一台的状态在切回后恢复。
- 车机无 SIM，不要用 `TelephonyManager` 判断通话或信号，应以 `PhoneDevice` 与 `PhoneCallState` 为准。

## 12. 错误处理与重试

| 场景 | 建议 |
|---|---|
| `NOT_READY` | 等待网关就绪后重试一次；先调用 `refresh()` |
| `NO_DEVICE` | 引导用户连接手机，不要自动重试 |
| `NO_CALL` | 状态已变化，刷新 UI 并禁用按钮 |
| `BLUETOOTH_OFF` | 引导打开蓝牙；监听 `connectionState` 恢复 |
| `NOT_SUPPORTED` | 隐藏入口；会议合并失败时提示“当前手机不支持会议” |
| `INVALID_ARGUMENT` | 输入侧校验，避免重复请求 |
| `PERMISSION_DENIED` | 申请权限后重试 |
| `BUSY` | 提示先处理等待/第二路，不要自动重试 |
| `INTERNAL` | 记录日志；可提示用户重试一次 |

原则：**只对 `NOT_READY` 做有限重试**，其余错误要么是状态问题，要么是能力问题，自动重试会放大异常。

## 13. 调试与问题排查

### 13.1 日志分级与开关

中间层所有日志统一经 `PhoneLog` 输出，格式为 `模块 | 内容`，TAG 与级别均可配置：

```text
I/BluetoothPhone: Engine | dial(138****8000): -> Demo Phone
D/BluetoothPhone: Hfp | 广播 android.bluetooth.headsetclient.profile.action.AG_CALL_CHANGED
D/BluetoothPhone: State | 归并 AA:BB:CC:DD:EE:01: 2 路 [ACTIVE:138****8000, HELD:139****0001]
I/BluetoothPhone: Engine | UI 阶段: ACTIVE -> MULTI_CALL
```

| 级别 | 内容 | 典型场景 |
|---|---|---|
| `NONE` | 关闭输出 | 量产稳定版本 |
| `ERROR` | 未预期异常 | —— |
| `WARN` | 权限缺失、反射失败、动作失败、AG 行为差异 | 量产推荐下限 |
| `INFO` | 生命周期、设备连接、通话阶段变化、动作结果 | 默认级别 |
| `DEBUG` | 每条 HFP 事件、状态归并摘要、重连、联系人同步 | 现场排查 |
| `VERBOSE` | 逐条 call 映射、AG 原始 Bundle、DTMF 单字符 | 深度定位 |

设置方式：

```kotlin
// 初始化时指定
BluetoothPhoneConfig(logLevel = PhoneLogLevel.DEBUG)

// 运行期动态调整，不需要重启中间层
BluetoothPhone.setLogLevel(PhoneLogLevel.DEBUG)
BluetoothPhone.setLogTag("CarPhone")
val level = BluetoothPhone.currentLogLevel()
```

号码统一脱敏为 `138****8000`，避免日志回传时泄露完整号码；设备 MAC 保持完整，便于与 `dumpsys` 对照。

常用命令：

```bash
adb logcat -s BluetoothPhone
adb logcat -s BluetoothPhone | grep -E "Engine|State|Hfp|Device"
adb shell dumpsys bluetooth_manager
adb shell dumpsys package <applicationId>
```

推荐排查顺序：

1. `Phone | init`：确认 mock 状态与日志级别。
2. `Hfp | HFP Client 代理就绪`、`Hfp | 蓝牙开关`：确认链路是否建立。
3. `Device | HFP 状态`、`Engine | 设备连接`：确认目标设备。
4. `Hfp | 广播`、`Hfp | 通话列表`：确认 HFP 原始上报。
5. `State | 归并`、`Engine | 通话快照`：确认归并结果是否符合预期。
6. `Engine | xxx 失败`：定位具体动作与失败原因。

重点确认：

- 应用是否持有 `BLUETOOTH_PRIVILEGED`。
- HFP Client 是否已连接（查看 `dumpsys bluetooth_manager` 中的 Headset Client 段落）。
- `isMock` 是否为预期值。

### 13.2 常见问题

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| 界面一直显示 Mock | 未显式初始化，且缺少系统 API/权限 | 检查签名、priv-app、`BLUETOOTH_PRIVILEGED` |
| `callState` 始终为空 | `BLUETOOTH_CONNECT` 未授予；代理未就绪；手机未连 HFP | 看 `events` 中的错误、`connectionState` |
| 会议按钮不出现 | `conferenceMergeSupported=false` | AOSP 无 CHLD=3 通道，需厂商方法/AT |
| 合并返回 `NOT_SUPPORTED` | 手机协议栈拒绝 CHLD=3 | 换机型验证；检查厂商 AT 命令 |
| 来电车机不响 | 带内铃声开启、音量/勿扰、权限 | 看 `isInBandRing`、通知音量 |
| 通话无声音 | 音频仍在手机、SCO 未建立、HAL 问题 | 看 `audio` / `audioRoute`，调用 `setAudioToCar()` |
| 保持时按钮变成接听 | 存在等待来电时 `CHLD=2` 会接听 | 使用 `canHold` / `canSwap`，不要直接发命令 |
| 挂断等待来电误挂当前 | AG 对 CHUP 处理不同 | 量产实测，必要时改 `CHLD=0` 厂商通道 |
| 联系人无姓名/头像 | 权限、号码格式、PBAP 未同步 | 检查 `READ_CONTACTS`、后 10 位匹配 |
| 时长比手机短 | 服务在通话后启动，HFP 无接通时间 | 属于协议边界，可接受 |
| 第二路来电显示成普通来电 | AG 上报差异 | 模块已归一化；确认 `active` 是否存在 |

## 附录 A　术语与缩写

本附录解释文档与代码中出现的协议缩写。

### A.1 蓝牙协议与角色

HFP 定义两个成对出现的角色：车机侧为 HF（免提），手机侧为 AG（音频网关）。文档中“车机”“HF”“HFP Client”指同一端，“手机”“AG”指另一端。

| 缩写 | 全称 | 中文 | 注释 |
|---|---|---|---|
| HFP | Hands-Free Profile | 免提协议 | 蓝牙 SIG 定义的免提通话协议，规定 AT 命令控制与 SCO 音频通道；本项目的主链路。 |
| HF | Hands-Free Unit | 免提设备 | HFP 的从端，只负责麦克风采集与扬声器播放；本项目里就是车机自身。 |
| AG | Audio Gateway | 音频网关 | HFP 的主端，一侧连接蜂窝网、一侧连接蓝牙，负责语音转发；通常是手机。 |
| HFP Client | HFP Client（HF 角色） | HFP 客户端 | Android 对 HF 角色的 API 命名，对应 `BluetoothHeadsetClient`。叫 Client 是因为车机是手机 HFP 服务的客户端。 |
| HFP AG | HFP Audio Gateway | HFP 服务端 | 手机侧角色，对应 Android 的 `BluetoothHeadset` 服务。部分车机系统默认只启用该角色，需确认 HFP Client 已开启。 |
| PBAP | Phone Book Access Profile | 电话本访问协议 | 同步通讯录与通话记录；本项目只触发同步，数据仍从 `ContactsProvider` 读取。 |
| A2DP | Advanced Audio Distribution Profile | 高级音频分发协议 | 音乐媒体音频通道，不承载通话语音。 |
| AVRCP | Audio/Video Remote Control Profile | 音视频远程控制协议 | 音乐播放控制；本项目未实现，车机通常需另行集成。 |
| SCO | Synchronous Connection Oriented | 同步面向连接链路 | HFP 承载通话音频的蓝牙链路，传统窄带为 8kHz 采样。 |
| eSCO | extended SCO | 扩展同步面向连接链路 | 带重传机制的 SCO，可承载宽带语音，抗干扰更好。 |
| WBS | Wide Band Speech | 宽带语音 | 16kHz 采样的高清语音，需 eSCO、mSBC 与双方支持；对应 `audioWideband`。 |
| mSBC | mono SBC | 单声道 SBC 编码 | WBS 使用的语音编码格式。 |

### A.2 HFP 命令与信令

| 缩写 | 全称 | 中文 | 注释 |
|---|---|---|---|
| AT | ATtention | AT 命令 | 源自调制解调器的命令集，HFP 用它控制手机。 |
| ATA | AT Answer | 接听命令 | 车机接听来电，对应 `answer()`。 |
| ATD | AT Dial | 拨号命令 | 车机发起呼叫，对应 `dial()` 与 `addCall()`。 |
| AT+CHUP | AT Channel Hang Up | 挂断命令 | 结束当前通话，对应 `hangup()`、`reject()`、`hangupWaiting()`。 |
| AT+CHLD | AT Call Hold and multiparty | 呼叫保持与多方通话 | 参数 0–3 控制保持、切换、接听等待与会议合并。 |
| CHLD | Call Hold | 呼叫保持 | `AT+CHLD` 的简称。`CHLD=0` 释放保持，`CHLD=1` 挂断当前接听等待，`CHLD=2` 保持或切换，`CHLD=3` 合并会议。 |
| AT+VTS | AT Voice Tone Send | 发送按键音 | 发送 DTMF 单字符，对应 `sendDtmf()`。 |
| AT+BVRA | Bluetooth Voice Recognition Activation | 蓝牙语音识别激活 | 由手机侧启动语音助手，车机只发触发命令；对应 `voiceRecognition()`。 |
| DTMF | Dual-Tone Multi-Frequency | 双音多频 | 电话按键音，用于 IVR 菜单、分机号、卡号；对应 `sendDtmf()`。 |
| IVR | Interactive Voice Response | 交互式语音应答 | 自动语音客服系统，靠 DTMF 按键交互。 |

### A.3 系统与工程

| 缩写 | 全称 | 中文 | 注释 |
|---|---|---|---|
| HMI | Human Machine Interface | 人机接口 | 座舱交互层；本项目指 Activity / Fragment / ViewModel，只读 `StateFlow`、只调公开 API。 |
| AOSP | Android Open Source Project | 安卓开源项目 | 指原生 Android 实现；用于说明某 API 未公开，例如 `CHLD=3`。 |
| HAL | Hardware Abstraction Layer | 硬件抽象层 | 底层硬件接口；音频 HAL 决定 SCO 路由与静音的实现方式。 |
| SIM | Subscriber Identity Module | 用户身份模块 | 车机无 SIM，不接入蜂窝网，通话能力完全依赖配对手机。 |
| VoIP | Voice over IP | 网络语音 | 微信等网络通话；HFP 不携带应用信息，需注入 `CallClassifier` 识别。 |
| URI | Uniform Resource Identifier | 统一资源标识符 | 本项目特指联系人头像的 `content://` 地址。 |
| MVVM | Model-View-ViewModel | 模型-视图-视图模型 | 演示应用采用的架构。 |
| NPE | NullPointerException | 空指针异常 | 调试章节提到的异常类型，例如反射缓存写入 `null` 引发的问题。 |

### A.4 关系速记

```text
车机（HF / HFP Client）  ←→  手机（AG）
        │  AT 命令：ATA / ATD / AT+CHUP / AT+CHLD / AT+VTS / AT+BVRA
        │  音频链路：SCO / eSCO（WBS 时使用 mSBC）
        └─ 旁路：PBAP 触发电话本同步 → ContactsProvider

HMI 位于车机侧最上层：只读 StateFlow，只调 BluetoothPhone 公开方法。
```
